# SAP Analytics Cloud Learning Portal

A browser-based learning hub for SAP Analytics Cloud (SAC), built around a
14-day beginner journey, the RetailCo case study, official SAP documentation
links, guided tasks, local notes, and copy-paste AI prompts.

The app runs as a static site today and now has a small frontend API boundary so
Azure Function Apps can be added later without rewriting the portal UI.

## Start Here

| Page | Purpose |
|------|---------|
| `index.html` | Landing page and track selector |
| `sap_sac_beginner_portal.html` | Version 1 beginner track |
| `sap_sac_beginner_portal_v2.html` | Version 2 beginner track, aligned with SAC 2025-2026 ODE |
| `sap_sac_beginner_portal_unified.html` | Unified v2 page using shared config, API client, and feature flags |
| `sap_sac_learning_portal.html` | Power BI transition track placeholder |

## Current Features

- Story-based lessons for absolute beginners
- RetailCo India practice company and generated CSV data
- Version 2 SAC navigation guidance for ODE, Data Panel, Just Ask, and geo enrichment
- Daily hands-on checklists, notes, and progress saved in `localStorage`
- Official SAP links, copy-paste prompts, and an optional Azure AI tutor widget
- Python data generation scripts with unit tests
- Feature flags and JSON content loading for a cleaner migration path

The Python data generator tests use the standard library test runner:

```bash
python3 -m unittest discover -s scripts/tests -p 'test_*.py' -v
```

```bash

```

Run the experimental modular generator:

```bash
python3 scripts/generate.py --experimental --seed 42
```

## Frontend API Boundary

`js/modules/core/api-client.js` is the frontend data boundary. It reads
`config/app-config.json` and defaults to static JSON files:

```json
{
  "environment": "static",
  "apiBaseUrl": "",
  "endpoints": {
    "featureFlags": "data/config/feature-flags.json",
    "storyScenes": "data/content/story-scenes.json",
    "glossary": "data/content/glossary-by-day.json",
    "characters": "data/content/characters.json"
  }
}
```

When Azure Functions are added, switch `environment` to `api`, set
`apiBaseUrl`, and point endpoint values at Function routes.

Planned Function endpoints:

- `/api/health`
- `/api/feature-flags`
- `/api/content`
- `/api/progress`
- `/api/chat`
- `/api/retailco-data`

Keep API keys and connection strings out of the frontend. Store them in Azure
Function App settings or local `local.settings.json`.

## Deploy

The current app can still deploy as a static site, including GitHub Pages,
because all default paths are relative.

For an Azure-ready deployment later, use:

- Azure Static Web Apps for the frontend
- Azure Functions for `/api/*`
- Azure Storage, Cosmos DB, or Table Storage for learner progress and content
- Azure OpenAI and Azure AI Search behind the `/api/chat` Function

For GitHub Pages, set `chatbot.apiUrl` in `config/app-config.json` to the full
deployed Azure Function URL. The widget remains visible but disabled with a
configuration message until that public URL is set.

## Notes

- Learner progress and notes currently stay in the browser via `localStorage`.
- The checked-in CSV files are learning artifacts generated by the scripts.
- `.DS_Store`, Python caches, local Azure settings, and environment files are ignored.
